# M4 plan: files

Date: 2026-11-19

## Scope

From the kickoff: our own native format, a plain-text, diff-friendly file
holding everything in the spec's native-format brief, versioned with
migrations and documented in `docs/format.md`; Fountain import and export,
round-trip tested; plain text and RTF import with auto-formatting into
elements; text-based PDF import through craft-pdf's reader; RTF, plain text
and HTML export; auto-save every 15 minutes after 10 seconds idle, plus rolling
timestamped backups, all through craft-atomic; crash recovery.

Spec items (`docs/SPEC.md`, "Files"):

| Spec item | Status |

## Approach

1. **`m4/native-format`** (`wordsmith-format::native`). A UTF-8 text file:
   a version line; a settings part (page setup, element styles, and every
   `app_data` entry, as sorted, pretty-printed JSON, one key per line so a
   change shows as a small diff); then the script, one paragraph per block:
   `@Element` (with optional attributes), the text with Fountain-style
   emphasis and backslash escapes, a blank line. Readers check the version and
   run migrations from older versions; unknown newer versions are refused with
   a clear message. Everything is bounded. `docs/format.md` documents it. The
   native extension is `.wss` (Wordsmith Script).
2. **`m4/fountain`**: the Fountain writer, emphasis kept both ways (bold,
   italic, underline runs), dual dialogue still read as plain dialogue, and
   round-trip tests: the three golden scripts and generated scripts survive
   Fountain → script → Fountain → script unchanged in elements and text.
3. **`m4/import`**: plain text and RTF (craft-rtf) into a script. The
   "is this a script?" question is a parameter: as a script, lines are
   classified by convention (scene-heading intros, capitals followed by
   dialogue, parentheticals, transitions ending in "TO:"); otherwise each
   paragraph becomes Action. Text-based PDF import reads each line's text and
   left edge with craft-pdf's reader and classifies by indent (the template's
   positions), so a PDF this app wrote comes back as the same elements.
4. **`m4/export`**: plain text (laid out with the elements' indents in spaces,
   no mores and continueds), RTF (craft-rtf writer, elements as indented
   paragraphs, emphasis kept, no mores and continueds) and HTML (one element
   per paragraph with a class, a small embedded stylesheet).
5. **`m4/save`**: open, save, save as, import and export in the editor with
   native dialogs; the window title shows the file name and unsaved changes;
   closing with unsaved changes asks first. Auto-save (on by default, every
   15 minutes, after 10 seconds without typing) writes the script to its own
   file when it has one; rolling backups (`<name> <timestamp>.wss` in a
   backups folder, 1,000 kept by default, at most 10,000, oldest removed) on
   every save. All writes through craft-atomic. App preferences (auto-save
   settings, backups, the M3 view settings, the personal dictionary) through
   craft-settings. *As built:* craft-settings needs an MPL-2.0 crate, so
   preferences are a JSON file of our own and the dictionary is craft-proof's
   file (decision 0020).

## Tests

- Native format: every kind of content round-trips exactly (paragraph
  elements and text, emphasis, line breaks, attributes, element settings,
  every `app_data` entry, page setup); a stored v1 fixture still reads;
  migrations run; damaged and hostile files are refused cleanly; the output is
  stable (save, read, save gives the same bytes).
- Fountain: round trips of the golden scripts and of every element; emphasis.
- Imports: classification of each element from text, RTF and PDF; a PDF this
  app exported comes back as the same elements.
- Exports: plain text columns, RTF readable by craft-rtf's own reader, HTML
  well-formed and escaped.
- Saving: save and open in the editor, dirty state, auto-save timing (with a
  test clock), backup naming and pruning, the settings store.
