# v0.3 plan: an interface that shows what the app can do

Date: 2026-11-20

## Why

v0.2 has the functions; the interface hides them. Today the window is a plain
menu bar, a one-line toolbar (undo, redo, the element box, zoom), the page, and a
status bar. Everything else is behind ten menus, the command palette, or one of
28 floating windows that open over the page:

- About, Beat, Bookmarks, Character Details, Check Format, Commands, Element Settings
- Go To, Header and Footer, Import, Keys, Macros, New from Template, Preferences
- Print, Recover Unsaved Scripts, Reformat, Replace Alias, Reports, Revision Sets
- Scene Numbers, Scene Properties, Sprint Finished, Title Page, Unsaved Changes
- Watermark, Welcome, Writing Statistics

The page is 8.5 in wide, so on a laptop or larger screen the space either side of
it is empty.

The owner asked for a ribbon like WordCraft's and side panels that use the space
beside the page. This plan does that, and turns most floating windows into panels
and ribbon controls the writer can see without hunting.

## What stays the same

- **Every control runs a command by id** through the one registry. The menus,
  keys, palette, CLI and MCP keep working unchanged, and the ribbon, panels and
  tests can be checked against the registry.
- **No screenplay behaviour changes.** This is interface only (decision 0030).
- **The clean-room and branding rules hold.**
  - WordCraft's interface is MIT OR Apache-2.0, so its widget code may be copied
    and marked.
  - Its labels are Word's, so ours are our own. There are no Home, Mailings or
    References tabs; the tabs are named for screenplay work.
  - No Discord or Share buttons, no ArtCraft name, logo or app icon, and no
    "Craft" in what we show.
- **Keyboard first.** Every ribbon control's tooltip shows its key. Nothing
  becomes mouse-only.

## Reuse

| Piece | Source | How |
| --- | --- | --- |
| Side rails, panes with title bars and resize edges, docking | `craft-ui` (`panes`, `panes::rail`, `docking`), already pinned at craft-libs `93dac78` | Dependency (not used yet; WordCraft builds its task panes on it) |
| Tab-strip fitting, toolbar fitting, icon buttons, widget-state theming | `craft-ui` (`tabs`, `layout`, `buttons`, `theme`) | Dependency |
| Ribbon widgets: large and small buttons, split buttons, groups with titles, menu buttons | WordCraft `crates/ui-egui/src/widgets*`, `ribbon/common.rs` at `f8ec3cc` | Copy, rename, mark as modified, record in `UPSTREAM.md`; cut the Word-specific parts |
| Groups that shrink to fit the window (full, compact, collapsed) | WordCraft `ribbon_fit.rs` | Copy and mark; it is self-contained |
| Design tokens (colors, type sizes, spacing) for light, dark and extra dark | WordCraft `theme.rs` (`Tokens`) | Copy the token idea, cut to what we use, with our own values |
| Icons drawn in code (no image files) | WordCraft `icons.rs` (its `Pen` on a 20 × 20 grid) | Copy the drawing helper; draw our own icons for screenplay work. Keep any general icons we take (cut, copy, undo, bold) as they are, with attribution |

This partly reverses `docs/REUSE.md`, which listed WordCraft's interface crate as
"not worth taking". We take only the ribbon frame, fitting, tokens and icon
helper, not its 106,000 lines or its Word command catalogue. Decision 0037 will
record it.

- **Quick-access row:** save, undo and redo; the script's name and save state;
  a command search box (the palette, always visible). The macOS menu bar keeps
  the full menus. On Windows and Linux, File opens the backstage (below) and the
  menu bar is hidden by default, with an option to show it.
- **Rails:** a narrow icon rail on each side of the window. A click opens that
  rail's panel; a second click on the same icon closes it. Panels resize and
  remember their width. Focus mode hides rails, ribbon and status bar.
- **Fit:** the page centres in what is left. When the window is narrow, panels
  float over the page instead of squeezing it. On a wide window both panels can
  stay open.

- **Become panels** (above): Bookmarks, Scene Properties, Character Details,
  Revision Sets, Scene Numbers, Check Format.

  Preferences, About.
- **Stay as dialogs**, with the shared look: Element Settings, Title Page,

## Status bar

- **Left:** page (label when locked) of pages, words, scene.
- **Middle:** the caret's element with "Return: … · Tab: …"; chips for revision
  mode (in the set's color), tracking, dual dialogue and text document.
- **Right:** sprint time, view switch icons, zoom slider with percent.
- **Clicks:**
  - the page or scene opens Go To;
  - the words open Statistics;
  - a chip opens its panel.

## Look

- **Tokens** for every color, size and space, in three themes. The page sits on
  a soft grey canvas with a shadow. Panels and ribbon share one surface color.
  Accents are used only for state (the current tab, toggles that are on,
  revision colors).
- **Type:** Inter for the interface (bundled), 12.5 pt body, 11 pt captions.
  Courier Prime stays on the page.
- **Icons:** our own, drawn in code on the 20-point grid in two colors. They
  include one per screenplay element, the views, revision set, lock, scene
  number, note, bookmark, beat, card, strip, sprint, compare, tracked change and
  watermark.
- **Hover help:** every control has a tooltip with the command's name, its key,
  and one line on what it does (from the registry's labels, plus a new
  `description` for each command).

## Risks

- **egui layout cost:** a ribbon and two panels redraw every frame. Panels show
  lists cached by script revision (as the scene list is today), and the
  per-keystroke budget is checked in M16.
- **Copied code drags in WordCraft's app type:** the ribbon widgets take
  WordCraft's `WordApp`. They are copied as functions over a small trait the
  editor implements (run a command, is it enabled, is it on), so nothing else
  comes with them.
- **Too many controls:** the ribbon shows the common commands large and the rest
  small or in menus. Group fitting folds groups on narrow windows. Nothing new is
  added to the ribbon that has no command behind it.
- **Looking like Word:** a ribbon is a common pattern, not Word's property, but we
  avoid Word's tab names, group names and layout. Our tabs follow how a
  screenplay is written and produced.
