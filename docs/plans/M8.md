# M8 plan: release

Date: 2026-11-19

## Scope

From the kickoff: `wordsmith-cli` (convert, export PDF, report) and the
`wordsmith-mcp` server with screenplay commands exposed as tools; installers
or bundles for macOS, Windows and Linux; a README with screenshots made by
the app's own offscreen renderer; a user guide in our own words under
`docs/guide/`; a CHANGELOG and a v0.1.0 tag. Publishing the release is a stop
rule: the project owner is asked first.

The definition of done also asks that every Verified and Sourced item for
M1 to M7 is implemented or listed in `docs/gaps.md`, that there are no known
crashes on the hostile-input corpus, and that typing stays responsive in a
150-page script (measured and recorded).

## Approach

1. **`m8/cli-mcp`.** The file commands (open, import, save, export) move from
   the interface to `wordsmith-format::commands`, so the window, the CLI and
   the MCP server share them (the window keeps asking for files with
   dialogs). `wordsmith-cli`: `convert <in> <out>`, `export-pdf <in> <out>
   [--revised-only] [--no-marks]`, `report characters|scenes <in> [<out.csv>]`,
   `info <in>` (pages, scenes, characters), and `mcp` (the MCP server over
   standard input and output on a headless session with every screenplay
   command, confined to `--read-root` / `--write-root` folders when given).
   The MCP server gains screenplay tools: open and save scripts, type text,
   set an element, list scenes and characters, export, and the page count,
   besides its general command tools.
2. **`m8/screenshots`.** An offscreen renderer for the interface: run the
   editor for a frame headlessly and rasterize egui's output on the CPU (its
   triangles, vertex colors and font texture) to a PNG, beside the page
   renderer the app already has. `cargo xtask screenshots` writes the
   README's pictures from a sample script (page view, index cards, story
   board, outline, a revised page).
3. **`m8/bundles`.** `cargo xtask bundle` builds a release bundle for the
   host: a macOS `.app` (Info.plist, binary, icon) in a zip, a Linux tarball
   with a `.desktop` file, a Windows zip. A release workflow builds all three
   on GitHub's runners when started by hand; it uploads them as build
   artifacts and publishes nothing.
4. **`m8/docs`.** The user guide (getting started, writing, views, files,
   production, outlining, keyboard, the CLI and MCP); README with the
   screenshots; CHANGELOG; a spec audit (every Verified and Sourced item for
   M1 to M7 checked against the code, the rest in `docs/gaps.md`); a
   hostile-input corpus test across every reader and importer; the typing
   measurement recorded.
5. **Release.** `cargo xtask ci` on main, then ask the project owner before
   tagging v0.1.0 and before anything is published.

Decision to record: release packaging and the CLI and MCP surface (0029).

## Tests

- CLI: each subcommand on a sample, bad arguments, exit codes.
- MCP: the new tools over the JSON-RPC handler; file tools confined to the
  given roots.
- Screenshots: the rasterizer draws a known shape and text; the xtask runs.
- Bundles: the macOS bundle builds and its binary runs `--version`.
- Hostile corpus: truncated, random and malformed files in every format,
  never a panic.
