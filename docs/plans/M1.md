# M1 plan: screenplay model and editor

Date: 2026-11-19

## Scope

From the kickoff, M1 covers: the element registry (every element in the
spec's element table, plus custom elements), each element mapped to a
paragraph style, scenes derived from Scene Headings, Return creating the
element's next element, Tab following the spec's Tab table including
scene-heading separators, change-element commands with Mod+0 to Mod+9,
casing rules, editable element settings (font, indents, alignment, spacing,
space before, next element, start new page, keep rules), and undo and redo
for all of it.

Spec items this milestone delivers (all from `docs/SPEC.md`):

| Spec item | Status in spec |
| --- | --- |
| A script is an ordered list of paragraphs, each with exactly one element type; element types work like styles | Verified |
| Element table: General, Scene Heading, Action, Character, Dialogue, Parenthetical, Transition, Shot, Cast List, New Act, End of Act, Outline 1/2/3, Note, Summary, custom elements | Verified / Sourced |
| Scene Heading, Character uppercase; Transition and Shot uppercase | Verified / Sourced |
| Scenes derived from Scene Headings | Verified |
| Return creates the element's next element; next element editable per element | Verified |
| Tab table (current element to Tab target) | Verified |
| Scene-heading separators ". " and " - " on Tab, stored per list and changeable | Verified / Sourced |
| Change element by command; Mod+0 to Mod+9 for the ten core elements; custom elements can have their own shortcut | Verified / Sourced |
| Option: element after Dialogue defaults to Character | Sourced |
| Per-element settings: font, size, style; alignment; line spacing 1, 1.5, 2, 3; space before 0 to 30 lines; left and right indents in inches; next element; start new page; paginate-as; shortcut | Verified |
| A command applies font and size to all elements but leaves bold and italic alone | Verified |
| Custom elements start from Action's settings | Sourced |
| The editor never blocks an unusual order | Verified |

Not in M1: pagination rules, (MORE)/(CONT'D) and page view (M2);
autocomplete, spelling, views and themes (M3); files (M4). Outline elements
exist in the registry now; showing and hiding them is M7.

## Approach

Branches, in order. Each merges only after `cargo xtask ci` passes.

1. **`m1/doc-app-data`.** Give `wordsmith-doc`'s `Document` a small
   `app_data` map (key to JSON), included in content comparison and cloning,
   so per-script data lives in the document and undo covers it. This is a
   general change, so it gets an `UPSTREAM.md` entry.
2. **`m1/elements`.** In `wordsmith-script`: the element registry
   (`ElementDef`: id, name, kind, casing, Tab target, blank-line-only Tab,
   paginate-as, shortcut, built-in flag), stored in `app_data`. All
   formatting lives in the element's paragraph style, the single source of
   truth: font, size, bold, italic, underline, indents, alignment, line
   spacing, space before, next element (`Style::next`), start new page
   (`page_break_before`), keep rules (`keep_next`, `keep_lines`,
   `widow_control`). The screenplay template uses the spec's geometry
   defaults. Scene index derived from Scene Heading paragraphs. Bundle
   Courier Prime (OFL-1.1) now, since every element uses it, and test 10
   characters per inch and 6 lines per inch at 12 pt.
3. **`m1/typing`.** Screenplay commands registered through the engine:
   typing with casing, Return, Tab (with separators), Backspace and Delete,
   caret movement and selection, change element (`element.set` plus one
   command per element with its shortcut).
4. **`m1/element-settings`.** Commands to read and change element settings,
   create and delete custom elements, apply font and size to all elements,
   and the Dialogue-next-is-Character option. All undoable.
5. **`m1/editor`.** The `wordsmith` desktop app on egui 0.36: one window per
   script, a continuous script view drawn from the layout through
   `wordsmith-render`, caret and selection from the layout's hit testing,
   keyboard and mouse mapped to commands through the registry, an element
   selector, an element settings dialog, a command palette, menus, and crash
   recovery switched on. egui's bundled fonts are switched off; the UI uses
   the fonts we already bundle.

## Design decisions to record in `docs/decisions/`

- Where screenplay data lives (`app_data`) and why.
- Casing: uppercase elements store uppercase text (typed text is converted,
  and changing a paragraph into an uppercase element converts it), so every
  export sees the real text. Not a display-only caps flag.
- Tab inside a Scene Heading: after a known intro with no separator yet,
  insert ". "; after the location with no time separator yet, insert " - ";
  on a blank Scene Heading, switch to Action per the Tab table; otherwise do
  nothing. Separators are stored per script.
- Return in the middle of a paragraph splits it and keeps the element;
  Return at the end creates the next element. Return on an empty paragraph
  behaves the same as at the end.
- Character + Tab when the line is not blank does nothing in M1 (M3 uses it
  to accept a suggestion).
- Defaults for elements the geometry table does not cover (Cast List, New
  Act, End of Act, outline elements, General).
- Parenthetical: switching an empty paragraph to Parenthetical inserts "()"
  with the caret between, as screenplay convention writes them in brackets.

## Tests

- Registry: every element in the spec table exists with the right style,
  casing, Return target and Tab target; custom elements start from Action.
- Return, Tab and change-element follow the tables; separators; casing on
  typing and on change; undo restores text and element in one step each.
- Element settings: each setting round-trips and is undoable; applying font
  and size to all elements leaves bold and italic alone.
- Scenes: index from Scene Headings, including an empty script and a script
  with text before the first heading.
- Courier Prime: 10 characters per inch and 6 lines per inch at 12 pt,
  through the layout.
- Hostile input: a malformed `app_data` entry falls back to the default
  registry instead of failing.
- Editor: commands reached by key bindings, checked headlessly through the
  registry and the key map; the window itself is checked by hand on macOS.

## Risks

- The editor is the largest piece and the hardest to test automatically.
  Logic stays in commands so tests cover it without a window.
- egui 0.36 and its dependencies may bring licenses outside the allowlist.
  The attribution check will stop the branch if so.
- Courier Prime has to be downloaded from its public source. That is
  recorded in `docs/provenance.md` and `ATTRIBUTION.md`.
