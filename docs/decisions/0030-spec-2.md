# 0030: SPEC-2 and what v0.1 built

Date: 2026-11-19 · Status: accepted

## Context

After v0.1.0 was tagged, the maintainers wrote a second specification,
prepared by clean-room methods (`docs/SPEC-2.md`), and chose to treat
everything built so far as correct rather than change it to fit the new
document: writers' scripts and habits should not shift under them.

SPEC-2 is broader than `docs/SPEC.md` (macros, reports, format checker,
read-aloud, collaboration, productivity) and labels each value [STD], [DEF],
[OWN] or [OPEN]. A few [STD] values differ from what v0.1 built from SPEC.md
and the public guides it cites.

## Decision

1. **Both specs stand.** SPEC.md remains the source for what v0.1 built.
   SPEC-2 is the source for new work. Where the two disagree, the built
   behaviour stays.
2. **Differences are questions, not changes.** Every place a SPEC-2 [STD]
   value differs from v0.1 is listed in `docs/history/spec2-audit.md` and asked in
   `docs/history/spec2-questions.md`. A built default changes only when the
   maintainers answer the question. When one does change, existing scripts keep their stored values
   and only new scripts get the new default.
3. **New work is additive.** Features SPEC-2 adds are built beside what
   exists, through the same command registry, `app_data` keys and native
   format, which may only grow (decision 0017). New format versions are
   added with migrations.
4. **Names stay ours.** SPEC-2's feature names are descriptions ("beat
   canvas", "navigator", "structure strip"). The product keeps its own names
   (Story board, Tables, Outline) and gives new features new names of its
   own. Other products' names stay barred (`docs/SPEC.md`, rule 2), even where
   SPEC-2 uses the word as a description.
5. **The project's rules still apply**: the license allowlist (decision
   0001), the clean-room rules (`docs/SPEC.md`), and the changes that need
   the maintainers first, such as a network or paid service (decision 0042).
   SPEC-2's [OWN] data (dictionary, thesaurus, names, voices, templates) must
   come from allowlisted sources or be written here.
6. **Out of scope until the maintainers say otherwise:** breakdown tagging,
   collaboration and the assistant (decision 0042 and ROADMAP), and third-party
   script formats (SPEC-2 section 20 asks for a separate interface spec).

## Revisit when

The maintainers answer a question in `docs/history/spec2-questions.md`, or
bring breakdown tagging, collaboration or the assistant into scope.
